## The five features, as agreed

### 1. Reply-with-quote (DMs and groups only)

Squad/staff channels already thread (`parent_id` + `Reply`); DMs and groups
have nothing. WhatsApp shape:

- A **Reply** action on every DM/group message (in the same place as react).
- The composer grows a small preview bar — author + first line — with an ✕.
- The sent message carries `quoted_id`; the bubble renders a tinted quote
  block (author + snippet, clamped) above the body. Tapping it scrolls to
  the original.
- Original soft-deleted (`deleted_at`)? The block says "Message deleted"
  and stops being a link. The quote NEVER re-shows deleted content.

### 2. Forwarding (multi-select)

- A **Forward** action enters select mode: tap messages to toggle
  (checkboxes), a bar shows the count and a Forward button.
- Destination sheet = your own chats from `listChats()` — the places you can
  already write. Sending posts each selected message (oldest first) into the
  destination **as a new message from you**, `forwarded = true`, rendered
  with a small italic "Forwarded" label.
- Forwarding a photo message forwards `attachment_path` (same object, no
  copy — see note under storage policies).
- No new permissions anywhere: sends go through the existing paths, so
  `can_dm`, announce-only and blocks all apply unchanged. A refused send
  surfaces the same error a typed message would get.

### 3. Emoji picker (curated, desktop only)

- A 🙂 button in every composer (squad channel, staff channel, DM/group
  thread, floating dock) opening a popover grid of ~60 curated emoji in a
  few categories. No search, no dependency.
- Click inserts at the cursor; the popover stays open for multiple picks;
  Escape or outside-click closes.
- **Hidden below the `md` breakpoint** — phone keyboards already do this.
- One component: `src/components/EmojiPicker.jsx`.

### 4. Chat button on staff pills

- A chat-bubble button joins the contact buttons on `SquadStaffCard` tiles
  (Home). Tap → `openConversation(profileId)` → navigate to the DM thread.
- Not shown for yourself. Where the server refuses (child account, blocks,
  `can_dm`), show the refusal message it returns — same handling as the
  New Chat picker. No client-side re-implementation of the DM rules.

### 5. Photo attachments (the ruling: open, like WhatsApp)

- A photo button in every composer; images only (jpg/png/heic/webp).
  Client-side downscale to ≤1600px JPEG (canvas) before upload; hard cap
  ~5 MB after compression.
- **One photo per message**, body optional. Upload first, then send —
  WhatsApp order, so no broken-image moment.
- Bubble shows a thumbnail; tap opens a full-size overlay. URLs are
  short-lived signed URLs, never public.
- Author-delete of the message also removes the storage object (best-effort,
  after the soft delete succeeds).
- Report/welfare loop: unchanged and sufficient — a photo message is
  reported exactly like a text one, and welfare sees it wherever it already
  would. Retention is out of scope (Phase 4).

## The migration — one file, `db/migrations/`

1. `messages.quoted_id uuid REFERENCES messages(id) ON DELETE SET NULL`.
2. `messages.forwarded boolean NOT NULL DEFAULT false`.
3. `messages.attachment_path text` (bucket-relative object name).
4. Relax `messages_body_check`: empty body allowed **only when
   `attachment_path` is present**; the 2000 cap stays.
5. Storage bucket `chat-media`, **private**, with policies:
   - INSERT: authenticated, path must start `"<own profile id>/"` — you may
     only upload into your own folder.
   - SELECT: an object is readable iff a non-deleted `messages` row you can
     read (messages RLS does the work) carries it as `attachment_path`.
     Forwarded messages reference the same object, so audience widens with
     the forward — accepted; the forwarder could equally have re-uploaded.
   - DELETE: own folder only.
6. Grants mirrored into `db/schema/grants.sql` if any table grant changes
   (docs-check rule 7).

Harness: `db/tests/chat-round-2.sql`, rolled-back pattern
(`claude/runbooks/db-harnesses.md`), deliberate-fail-first per assert —
including: empty body WITHOUT attachment still refused; empty body WITH
attachment accepted; quote of a deleted message returns its `deleted_at`;
a non-member cannot read another thread's object row.
