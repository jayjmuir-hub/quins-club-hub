## ⚠️ The four things worth reading before you touch anything

**1. The safeguarding bug, and why it hid.** `src/lib/ageGroup.js` decides whether a
player may hold their own email and phone. The regex was `/^u(\d{1,2})\b/i`. `\b` needs a
word boundary after the digits and **a letter is a word character**, so `U12G QR` matched
nothing, the band came back `null`, and `allowsOwnContact` reads `null` as "a senior side:
adults" → **true**. The app offered a 12-year-old girls' squad the child's own contact
fields. Fixed with a negative lookahead. The lesson is the null default, not the regex:
**an unparseable name fell through to the least safe answer.**

**2. I gave Jay a wrong DNS diagnosis and he nearly acted on it.** I queried SPF/MX at
`send.adhquins-clubhub.com`, got `NoAnswer`, and told him the records were missing and
were causing the spam. **Resend puts the bounce domain one level BELOW the sending
domain** — the records are at `send.send.adhquins-clubhub.com` and all three were
Verified. His screenshot disproved me. He was one step from editing DNS that did not need
editing. **Read the provider's own dashboard before diagnosing its DNS.**

**3. I overstated a bug, and this project already has a rule about that.** I wrote in
three code comments and a test name that the parent-phone bug "DESTROYED numbers on any
save — the most destructive bug found in this app so far". Fault injection disproved it:
reverting the fix left the untouched-save test **green**, which is only possible if the
value survived. All four comments corrected. A migration header in this repo already
says *overstating a risk is how the next person stops believing the warnings*.

**4. Three tests that could not fail.** An RLS harness that looked up the membership id
*as the caller under test* — an unauthorised caller cannot see the row, so it passed NULL
and got "no longer exists", a refusal that proved nothing. **Every case "passed" without
reaching the authorisation check.** A StrictMode test using `rerender`, which re-renders
the same mounted component and never re-runs the effect. A localStorage `setItem` test
asserting on the list when the state is already set before the write throws. All three
passed with the fix deliberately removed. **Fault-inject, or you have decoration.**

Two more, cheaper: `tests/scope.test.js` asserted `expect(select).toHaveBeenCalled()`,
true whether or not the read was scoped; `tests/memberships.test.jsx` mocked `.select()`
resolving directly, so it could not tell a scoped read from an unscoped one.

**And one crash that shipped.** `displayName` was declared inside a `.map` callback;
moving rows into the Sheet moved them out of that closure → ReferenceError → **the whole
screen went blank**. Found by a subagent, not by me re-reading my own diff.
