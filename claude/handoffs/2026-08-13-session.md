## ⚠️ The five things this session got WRONG

Kept because each cost time and each is repeatable.

1. **Predicted `auth.users` would not survive a restore. It did.** Named in the
   audit AND the runbook as the most likely failure. Restored cleanly, all 8.
   **Sound reasoning, wrong answer** — and the whole argument for drilling
   rather than reasoning.
2. **Recommended a Supabase branch to test a migration. Branching does not work
   on this project.** `MIGRATIONS_FAILED`, zero tables. A branch replays the
   parent's migration HISTORY, and this project's history has 12 stale
   `accept_invite_multi_target` rows. ⚠️ **Both facts were already written down
   separately and nobody had put them together.** Cleaning
   `schema_migrations` is now a PREREQUISITE for having a staging environment.
3. **Ran `docs:check` before committing instead of after, and CI caught it.**
   `RESTORE.md` warns about precisely this, and the rule had been followed
   correctly an hour earlier. **After `git add` is necessary and not
   sufficient.**
4. **Claimed a new advisor warning meant the database had changed.** It had not
   — `events_result_from_components` had been unpinned since 12 Aug and repo
   and live matched exactly. ⚠️ **An advisor list that changes is not evidence
   the database changed.** Jay's "check the repo" is what settled it.
5. **Three failed attempts to slice `App.jsx` in a source-text test.** Sliced on
   `SIGNED-IN` → hit the routing essay; from byte 0 → hit `<AppShell>` in a
   comment; from `<Routes>` → hit `<Routes>` in a comment. ⚠️ **This repo
   comments heavily and quotes real JSX while doing it**, so any source
   assertion must anchor on something no comment says.
