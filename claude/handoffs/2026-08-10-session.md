## ⚠️ The four defects, and why they mattered

**The offline cache was not per person.** `vite.config.js` cached
`GET /rest/v1/*` in Cache Storage, which is keyed by URL and scoped to the ORIGIN.
`listClubMembers()` is unfiltered, so its url is byte-identical for an admin on
/admin/accounts and a coach on /approvals — an admin's club-wide member list, every
family's name, email and phone, stayed on a shared laptop after sign-out for
NetworkFirst to serve to the next person offline.

⚠️ **This was CONFIRMED BY INSPECTION on the deploy preview before the fix, not
just read out of the code.** The exact entry was found sitting in Cache Storage.
`src/lib/apiCache.js` purges on both sign-out paths and on any change of owner;
PR #4 then stopped the club-wide reads being cached at all.

**A token refresh unmounted the routed screen.** `MembershipProvider` keyed its
effect on the `session` OBJECT, which supabase-js rebuilds on every auth event
including the hourly refresh — so `loading` went true, `AppShell`'s `ready` gate
went false, and an open EventForm sheet vanished mid-edit. Keyed on the uid now.

**`NamePrompt` never primed `useMyProfile`'s cache**, so a first sign-in answered
the name gate and then read as nameless for the rest of the session.

**The membership-load error state had no sign-out** — the one branch of `AppShell`
not honouring "someone who cannot get in must always be able to get out".

## ⚠️ Two lessons about test data, which cost the most time

**1. Judge design against real data, not seed data.** A restructure of the schedule
(month grouping, constants hoisted into headers) was designed, agreed by Jay, and
then dropped — because a realistic September was seeded first and the existing list
turned out to read fine. Matches, socials and a second squad break the trainings up
on their own. The "wall of identical rows" was an artefact of a database holding one
squad and one repeating series. Shipping it would also have broken the two-squad
admin view, where the squad chip proposed for removal is doing real work.

**2. The fixtures do not resemble production, and that is why bugs ship.** Every
training in `tests/dashboard.test.jsx` is NAMED ("U10 skills session"); every
session in the real database is titled "Training". So the dashboard hero's
"NEXT TRAINING · U16B CONTACT" over a 42px "TRAINING" had no test that could see
it. The same shape appeared twice more:

- "Fixtures to play" counted every future event. **Both failing tests were pinning
  the bug**, and one said so out loud: "Only NEXT_MATCH and SOONER_TRAINING are
  still to come" — a match and a training, asserted as two fixtures.
- `loadMyMemberships` (9 Aug) had two tests that asserted the broken behaviour.

**The seeded September is worth keeping for this reason.** Removal is one line —
see `claude/state-of-play.md`.

## Repository guardrails, all new today

`main` can no longer be pushed to directly, force-pushed or deleted; `test` and
`docs-check` must pass before a merge; branches delete themselves after merging;
squash is the only merge method. Owner bypass is deliberately ON — the guard is
against accidents, not decisions.

⚠️ **`[skip ci]` AND REQUIRED CHECKS ARE NOW IN TENSION.** `CLAUDE.md` rule 3
recommends `[skip ci]` for docs-only commits. It also stops the required workflows
running, so the checks sit pending forever and the PR cannot merge. Not resolved —
`CLAUDE.md` still says the old thing.

## ⚠️ Traps hit while working, worth knowing

- **`git checkout -- <file>` on an UNSTAGED file wiped a finished fix.** Exactly
  what `CLAUDE.md` rule 6 warns about. Commit before injecting a fault.
- **A shallow clone implies `--single-branch`.** `git branch -r` showed only
  `origin/main` and looked like every other branch had been deleted; the GitHub API
  said otherwise. `claude/changelog.md` records a previous session falling for the
  same thing. It also breaks `--force-with-lease`, which cannot verify a ref it has
  never fetched — name the expected SHA explicitly.
- **A test rewrite silently dropped two tests.** The suite went from 1500 to 1499
  and stayed green. Caught only by noticing the count moved by less than the number
  of tests added.
- **The changelog coverage check demands the previous tip on every branch.** CI
  passes anyway because it tests the MERGE commit, whose first parent is `main` —
  so a local failure here is usually a false alarm. Working on a single-commit
  branch makes the local check meaningful again.
